# 全国中继数据网站计划

状态：规划中

本文档描述一个与固件仓库分离的全国中继数据服务。目标是让爱好者可以提交和核验中继信息，同时让固件项目只消费经过审核、可回滚的稳定数据。

## 1. 产品边界

网站负责：

- 地图、地区筛选、呼号和频率搜索；
- 用户注册、登录和协作身份；
- 新增、修改、停用中继的提交；
- 自动校验、人工审核和修改历史；
- 发布数据快照，并导出 JSON/CSV；
- 为固件构建提供稳定的数据输入。

固件仓库负责：

- 固件源码和构建脚本；
- 已核验的固件 bin；
- 固件可以消费的数据格式；
- 从已发布数据快照生成或接收 `repeaters.bin`、`tails.bin`。

网站不直接修改固件，也不应该让未审核的网页数据自动进入正式固件。

## 2. 登录和可见性

### 2.1 推荐规则

| 身份 | 查看公开数据 | 提交修改 | 审核发布 | 管理用户 |
| --- | --- | --- | --- | --- |
| 未登录访客 | 可以 | 不可以 | 不可以 | 不可以 |
| 已注册用户 | 可以 | 可以 | 不可以 | 不可以 |
| 审核员 | 可以 | 可以 | 可以 | 不可以 |
| 管理员 | 可以 | 可以 | 可以 | 可以 |

注册用户至少需要：

- 唯一用户名；
- 邮箱或其他可验证联系方式；
- 密码或受支持的第三方登录方式；
- 同意数据贡献规则和隐私政策。

第一版建议使用邮箱验证。密码只保存经过 Argon2id 或 bcrypt 等专用算法处理后的摘要，不保存明文；登录、注册、找回密码和提交接口都需要限流。

### 2.2 数据可见性

数据记录分为以下状态：

- `draft`：用户自己的草稿，其他用户不可见；
- `pending`：已经提交、等待审核，默认不进入公共搜索；
- `published`：审核通过，可以被所有人查看和下载；
- `retired`：已停用或确认过期，保留历史但默认不作为可用频率推荐。

如果以后确实需要“登录后才能查看”某些内容，可以只对草稿、审核记录、维护者信息或内部备注设置登录限制，不建议把全部公开频率藏在登录墙后面。

## 3. 数据模型

每条中继记录至少包含：

| 字段 | 说明 |
| --- | --- |
| `name` / `callsign` | 台站名称、呼号或标识 |
| `province` / `city` | 省、市及更细的地理区域 |
| `latitude` / `longitude` | 可选的地图位置；精度不足时不要强行填写 |
| `output_frequency` | 下行/接收频率，建议使用整数 Hz 存储 |
| `input_frequency` | 上行/发射频率，建议使用整数 Hz 存储 |
| `offset` | 收发差和偏移方向 |
| `tone` / `mode` | CTCSS、DCS、模拟/数字模式 |
| `status` | `draft`、`pending`、`published`、`retired` |
| `source` | 信息来源、公告、台站或核验说明 |
| `verified_at` | 最近一次核验时间 |
| `submitted_by` / `maintained_by` | 提交者和维护者 |
| `notes` | 覆盖范围、使用限制和其他说明 |

频率、偏移、亚音和模式应使用结构化字段，不要只把它们拼在备注里。这样才能做范围校验、重复检测和稳定导出。

## 4. 数据工作流

```text
注册/登录
    ↓
提交新增或修改
    ↓
自动校验：频率、偏移、亚音、重复记录、必填字段
    ↓
人工审核：来源、核验时间、台站状态
    ↓
发布数据快照
    ↓
导出 JSON/CSV → 生成固件中继数据 → 发布新固件
```

任何修改都应保留：修改前内容、修改后内容、操作者、时间、审核人和审核意见。错误数据应通过回滚或新版本修正，不直接删除历史记录。

## 5. 页面和接口（MVP）

第一版页面：

1. 首页地图和地区筛选；
2. 中继详情页；
3. 注册、登录和找回密码；
4. 新增/修改申请表；
5. “我的提交”页面；
6. 审核员队列和变更对比页面；
7. 数据导出页面。

第一版接口可以围绕以下能力设计，不预先锁死具体框架：

- `GET /api/v1/repeaters`：查询已发布数据，支持地区、频率、模式和状态筛选；
- `GET /api/v1/repeaters/{id}`：查看公开详情；
- `POST /api/v1/submissions`：注册用户提交新增或修改；
- `GET /api/v1/submissions/me`：查看自己的提交；
- `POST /api/v1/moderation/{id}/approve`：审核员发布；
- `POST /api/v1/moderation/{id}/reject`：审核员退回并附原因；
- `GET /api/v1/exports/{version}`：下载指定版本的 JSON/CSV。

所有写接口都需要身份认证、权限检查、输入校验和审计记录。公共查询接口可以只读开放，并设置合理的分页和限流。

## 6. 仓库和部署边界

建议拆成三个独立部分：

1. `uv-k5-losehu132-wrdzgzs`：固件源码、发布 bin 和导出格式说明；
2. `repeater-data`：规范化中继数据、审核历史和发布快照；
3. `repeater-web`：前端、API、注册登录和审核后台。

网站数据库、账号配置、邮件配置和运行日志不能提交到固件仓库。导出到固件仓库之前，应先经过数据版本标签和构建检查。

## 7. 分阶段计划

### Phase 0：规则和数据格式

- 确定字段、单位、状态和许可证；
- 清洗现有 430 条中继记录；
- 确定重复记录规则和审核标准；
- 定义 JSON/CSV 导出格式。

验收：可以从一份数据文件稳定生成校验报告，不依赖网站运行。

### Phase 1：只读数据站

- 导入第一版数据快照；
- 实现地图、搜索、地区筛选和详情页；
- 展示数据来源、核验时间和状态；
- 提供 JSON/CSV 下载。

验收：未登录用户可以查到已发布中继，并能追溯数据时间和来源。

### Phase 2：注册和提交

- 实现邮箱验证、登录、退出和找回密码；
- 注册用户可以提交新增、修改和停用申请；
- 增加“我的提交”和提交状态；
- 增加登录、注册、提交接口限流。

验收：普通用户不能直接改线上数据，只能产生可审核的申请。

### Phase 3：审核和历史

- 实现审核员角色和审核队列；
- 显示变更前后对比；
- 支持通过、退回、合并重复、标记过期；
- 保留完整审计记录和回滚入口。

验收：每条公开数据都能找到来源、提交者、审核人和版本。

### Phase 4：固件导出

- 根据已发布快照生成 JSON/CSV；
- 校验输出中的频率、偏移、亚音和容量限制；
- 自动生成 `repeaters.bin`/`tails.bin`；
- 在 CI 中构建并保存带版本号的产物；
- 由维护者确认后再更新固件仓库的 release。

验收：同一数据版本可以重复生成相同 SHA-256 的导出文件，错误数据不会自动进入正式固件。

## 8. 风险和约束

- 中继频率会变化，网站必须显示核验时间，不能宣传为永久准确；
- 用户提交不等于事实，必须保留来源和审核状态；
- 注册系统涉及密码、邮箱和个人信息，应单独保护，不写入公开数据仓库；
- 地理位置可能涉及台站隐私，未经确认时只显示城市或模糊位置；
- 固件导出属于发布流程，必须保留版本、校验和回滚能力；
- 不同设备的 EEPROM 容量和固件版本可能不同，导出器需要明确兼容目标。

## 9. 第一版完成标准

- 未登录可以搜索和查看已发布中继；
- 注册并验证邮箱后可以提交修改，但不能直接发布；
- 审核员可以查看差异、审核、退回和回滚；
- 每条公开数据显示来源、状态和最近核验时间；
- 可以导出带版本号的 JSON/CSV；
- 固件仓库只接收审核后的数据和可复核的构建产物。
